# Phase 2 HBM controller experiments

Generated by `make hbm` (`sim/analytic/hbm.py`). Do not edit by hand. Spec and decisions: [`docs/spec/hbm.md`](../spec/hbm.md).

One pseudo-channel (PC) is simulated cycle by cycle at the controller clock (1.2 GHz, one 32 B burst per cycle), with every command checked by the timing checker `Dram` (a violation aborts the run). 30 us per run after a 3.3 us warm-up, seed 1. Utilization = fraction of cycles the PC data bus carries a burst (1.0 = 38.4 GB/s per PC, 1.23 TB/s per stack). Closed loop: the controller queues are kept full (saturation). Defaults: read queue 32, write queue 16 granules, adaptive page policy, per-bank refresh, <= 85 C.

Patterns (addresses through the memmap.md hash, `isa.hbm_fields`):

- `seq_read`: 8 cores stream contiguous regions in 2 KiB requests (decode weights, KV scans).
- `seq_read_5pct_kv_write`: the same plus 5% random 256 B writes (decode KV appends).
- `seq_read_write_3to1`: sequential reads and writes 3:1 (prefill activations, spills).
- `rand_256B_read`: random 256 B granules (paged KV gathers, sparse-attention blocks).
- `rand_64B_read`: random 64 B reads (worst case for activations).
- `engram_264B_rows`: random 264 B rows of a contiguous table (DeepSeek Engram; 1-2 granule pieces per row).

## H1. Page policy (saturation utilization)

| pattern | adaptive | open | close | ACT per 1k bursts (adaptive) |
|---|---|---|---|---|
| seq_read | 0.991 | 0.976 | 0.939 | 35 |
| seq_read_5pct_kv_write | 0.954 | 0.938 | 0.916 | 44 |
| seq_read_write_3to1 | 0.905 | 0.860 | 0.720 | 40 |
| rand_256B_read | 0.967 | 0.944 | 0.967 | 125 |
| rand_64B_read | 0.424 | 0.423 | 0.424 | 500 |
| engram_264B_rows | 0.894 | 0.833 | 0.894 | 223 |

`engram_264B_rows`: 0.917 of the transferred bytes are row bytes (whole 32 B bursts), so useful bandwidth is that times the utilization.

`rand_64B_read` is bound by the four-activate window: 4 ACTs per tFAW (18 cycles) x 2 bursts = 0.44.
