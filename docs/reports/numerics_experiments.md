## E1. Block-scale fold into E4M3 (`cvt *_E4M3`) vs the exact BF16 path

Weights `[256 x 6144]` (MiniMax expert `w1` input width), quantized with the published recipes (NVFP4: FP32 tensor scale amax/(448*6), E4M3 scale per 16; MX: OCP v1.0 shared exponent per 32). The fold writes E4M3 elements and one power-of-two FP32 column scale per (row, 256-deep K tile). Activations: 64 BF16 rows with 16 outlier channels (x30).
Errors are relative Frobenius norms. `fold W`: folded vs exact dequantized weights. GEMM columns are relative to `X_bf16 @ W_exact`: `fold`: folded weights, BF16 activations (isolates the fold); `A8`: E4M3 per-row activations (what every FP8 GEMM pays); `fold+A8`: the MXU FP8 path; `A4`: NVFP4 activations (W4A4, as MiniMax is served on Blackwell); `BF16 path`: `cvt NVFP4_BF16` through the bit-accurate MXU model.

## E2. Hyper-connection mixer precision (HC-2)

Toy 80-sublayer mHC network (d = 256, 4 streams, 20 Sinkhorn iterations, vocabulary 4096, 256 tokens, 3 seeds); only the `[4d x 24]` mixer projection changes between variants. `alpha` scales the mixer logits (1: typical, 4: stress). Mean KL(FP32 reference || variant) of the final next-token distribution. `null` = FP32 with the summation order reversed (benign-noise floor). `BF16 hi/lo` = two BF16 passes over `W_lo` then `W_hi` (the stream is exact in BF16, so this equals `BF16X3`). `stream FP32` removes the BF16 rounding of the residual stream to expose each variant's own contribution.
